# Navigation Architecture — Enterprise Mega Menu and Footer

## Purpose

This document defines the current public navigation standard for AlgonquianRealEstate.com.

The navigation must organize the public website around six visitor-facing business areas while keeping authenticated operating systems separate from the public header. It must support property owners, acquisitions, investors and capital relationships, property services, the Algonquian Real Estate Technology Division, and company information.

The approved model is a **6 × 6 enterprise mega menu**:

- Exactly 6 primary desktop navigation items.
- Up to 6 columns under each primary item.
- No more than 6 primary links per column.
- 4 structured footer columns.
- One persistent primary conversion action: **Submit a Property**.
- Responsive desktop, tablet, and mobile behavior.

## Primary Header Navigation

1. Property Owners
2. Acquisitions
3. Investors & Capital
4. Services
5. Technology
6. Company

### Header Utility Actions

Keep utility actions outside the six primary navigation items:

- Search
- Buyer Login
- Client Portal
- Contact
- **Submit a Property**

`Submit a Property` is the primary gold CTA.

On narrower desktop widths, secondary utility labels may collapse to accessible icons before the six primary navigation labels are compressed or allowed to overflow.

# Mobile Navigation Standard

Mobile navigation must use the same six primary sections as desktop.

## Required first-tap behavior

Tapping the hamburger control must immediately reveal the six primary navigation sections:

1. Property Owners
2. Acquisitions
3. Investors & Capital
4. Services
5. Technology
6. Company

The user must **not** be required to tap a second generic `Menu` control before the six sections become visible.

Each primary section then expands independently to show its column headings and links. Do not render all links as one continuously expanded list.

When the mobile navigation closes:

- Reset expanded submenu state as appropriate.
- Restore focus to the hamburger control.
- Keep `aria-expanded` values synchronized with visible state.

### Mobile Utilities

Keep these actions clearly available inside the mobile drawer:

- Submit a Property
- Buyer Login
- Client Portal
- Search
- Contact

`Submit a Property` remains the visually dominant CTA.

---

# Desktop and Tablet Responsive Standard

The navigation must not overflow horizontally.

Recommended behavior:

- **1400px and wider:** full six-item primary navigation and text utility actions.
- **1100–1399px:** preserve the six primary labels; collapse secondary utilities to accessible icons where needed.
- **768–1099px:** compact primary navigation or tablet mega-menu treatment; utilities remain compact.
- **Below 768px:** hamburger navigation with immediate six-section display and accordion submenus.

Do not solve overflow by shrinking the primary navigation text to illegible sizes.

---

# Mega-Menu Visual Standard

Desktop mega menus should use:

- Maximum content width around 1,440px.
- Six equal-width columns where screen width permits.
- Three-column fallback on smaller desktop/tablet layouts.
- White or very light-gray panel background.
- Dark navy headings.
- Gold section accents.
- Teal hover and active states.
- Clear spacing or separators between columns.
- Consistent link spacing.
- Visible keyboard focus states.
- One highlighted promotional panel per menu where practical.

The navigation should remain visually consistent with the Algonquian Real Estate navy, gold, teal, white, and neutral interface system.

# WordPress Implementation Notes

Recommended WordPress menu locations:

```php
register_nav_menus(
    array(
        'algq_primary_menu'       => __( 'Algonquian Primary Mega Menu', 'algq-real-estate-platform' ),
        'algq_utility_menu'       => __( 'Algonquian Utility Navigation', 'algq-real-estate-platform' ),
        'algq_mobile_menu'        => __( 'Algonquian Mobile Navigation', 'algq-real-estate-platform' ),
        'algq_footer_company'     => __( 'Footer Company Links', 'algq-real-estate-platform' ),
        'algq_footer_property'    => __( 'Footer Property & Services Links', 'algq-real-estate-platform' ),
        'algq_footer_investors'   => __( 'Footer Investor & Platform Links', 'algq-real-estate-platform' ),
        'algq_footer_legal'       => __( 'Footer Resources & Legal Links', 'algq-real-estate-platform' ),
    )
);
```

The active WordPress theme/header layer may own the actual menu renderer. The Platform repository should document and test the contract without assuming a shortcode exists unless that shortcode is actually registered in canonical source.

Do **not** rely on undocumented or legacy `[algq_mega_menu]` / `[algq_footer_links]` shortcode names as production interfaces unless they are explicitly implemented and registered in the current Platform Plugin.

---

# WPBakery Rule

Where navigation-related public content is embedded in WPBakery content, use valid paired shortcode syntax:

```text
[vc_column_text]
Content
[/vc_column_text]
```

Never use `</vc_column_text>`.

# Production Acceptance Criteria

- Exactly six public primary header links are visible on desktop.
- Primary labels are `Property Owners`, `Acquisitions`, `Investors & Capital`, `Services`, `Technology`, and `Company`.
- Each primary menu supports no more than six content columns.
- Each column contains no more than six primary links.
- The footer contains exactly four structured columns.
- `Submit a Property` remains a prominent conversion action on desktop and mobile.
- Internal administrative routes are not exposed as unrestricted public navigation.
- Buyer, client, document, funding, CRM, underwriting, offer, automation, and administrative routes enforce their required access controls.
- Desktop navigation does not overflow at supported breakpoints.
- Mobile hamburger first tap reveals the actual six-section menu immediately.
- Mobile sections use accessible accordion behavior.
- Keyboard navigation and visible focus states are supported.
- Menu labels remain consistent across public pages and platform documentation.
- WPBakery syntax is valid where used.
- Open Space & Community Land and Land, Names & Living History are integrated without creating additional top-level navigation items.
