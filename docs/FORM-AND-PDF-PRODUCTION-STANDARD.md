# Algonquian Real Estate Form & PDF Production Standard

**Classification:** Required production release gate  
**Scope:** Every Algonquian Real Estate WordPress plugin that renders, receives, processes, stores, exports, emails, signs, or generates data from a form.

## 1. Governing rule

No form is production-ready merely because it renders or submits successfully. A form is production-ready only after it passes validation, authorization, privacy, persistence, delivery, accessibility, audit, failure-mode, and end-to-end workflow tests.

Any PDF generated by an Algonquian plugin must remain in protected platform storage and must also be registered as a private WordPress Media Library attachment record and/or delivered through the approved mail path. The default ARE archival mailbox is `algonquianre@gmail.com`.

## 2. Required controls for every form

Every state-changing form must implement all applicable controls below.

### Request security

- WordPress nonce tied to the exact action.
- Capability check for internal, administrative, buyer, client, lender, or other protected workflows.
- Record-level authorization when a form acts on a specific deal, document, buyer, funding record, property, or client.
- `POST` for state-changing requests.
- CSRF protection independent of browser-side JavaScript.
- Safe redirect targets using WordPress-safe redirect APIs.
- No trust in hidden fields for authorization, pricing, ownership, deal access, or entitlement decisions.

### Public-form abuse controls

Public forms must use layered anti-abuse controls appropriate to the workflow:

- Honeypot field.
- Minimum-submit-time check.
- Server-side rate limiting.
- CAPTCHA/Turnstile integration point for high-volume or attacked forms.
- Duplicate-submission/idempotency key when a retry could create a second business record.

### Validation and normalization

- Required-field validation on the server.
- Type validation for email, phone, dates, numbers, currency, percentages, URLs, IDs, and enumerations.
- Normalized email, phone, address, parcel, UUID, and identifier formats where applicable.
- Explicit allowlists for status, role, stage, document type, property type, transaction type, and other controlled values.
- Bounds checks for numeric fields.
- Rejection of impossible or contradictory state transitions.
- Browser validation may improve UX but must never be the sole validation layer.

### Sanitization and output safety

- Sanitize every untrusted input before persistence or use.
- Escape output for the exact HTML/attribute/URL/JavaScript context.
- Protect CSV exports against formula injection.
- Do not log passwords, authentication tokens, full payment-card data, SMTP credentials, or other secrets.

### Consent and privacy

Forms that collect personal information, marketing consent, NDA acceptance, seller authorization, terms acceptance, privacy consent, or electronic-signature consent must persist sufficient evidence, including as applicable:

- Consent type.
- Consent/document version.
- Acceptance timestamp.
- User/account ID when authenticated.
- Related deal/property/document ID.
- Privacy-preserving IP/network evidence when appropriate.
- User-agent evidence when appropriate.
- Immutable acceptance UUID.

Consent checkboxes may not be pre-checked.

### File uploads

Any form accepting attachments must enforce:

- Allowed MIME-type allowlist.
- Extension/MIME consistency checks.
- Maximum file size.
- Randomized server filename.
- Malware/virus scanning integration point.
- Private storage for confidential seller, buyer, lender, client, deal, identity, financial, inspection, or legal files.
- SHA-256 integrity hash for controlled documents.
- Authorized download controller instead of direct public file URLs.
- Audit event for upload, replacement, download, and deletion.

## 3. Persistence and workflow integrity

- Persist the submission before sending secondary notifications.
- Use database transactions or compensating logic where partial persistence could corrupt a workflow.
- Use idempotency protection for cross-plugin handoffs, webhooks, payments, deal creation, entitlement creation, document generation, and automation jobs.
- Preserve one authoritative owner for each business object.
- Deal Intake owns submission-time seller/property records until controlled CRM handoff.
- Pipeline CRM owns the canonical deal record and lifecycle.
- MAO Engine owns underwriting calculations and approved underwriting snapshots.
- Offer Generator owns offer/proposal records.
- Document Library owns controlled document metadata and packages.
- PDF & Signature Engine owns rendered PDF records, file hashes, signature requests, and execution evidence.
- Funding Tracker owns funding/capital tracking records.
- Buyer Portal/Marketplace enforce buyer identity and deal-specific access.
- Automation Engine owns automation execution state and retries.

## 4. User experience requirements

Every form must provide:

- Explicit field labels.
- Required-field indicators.
- Accessible validation messages.
- Error summary when multiple fields fail.
- Success confirmation that does not expose sensitive identifiers unnecessarily.
- Preserve safe user-entered values after recoverable validation errors.
- Keyboard operation.
- Visible focus states.
- Screen-reader-compatible status/error messaging.
- Responsive layout.
- Duplicate-click/submission protection on slow requests.

## 5. Notifications

Where the workflow requires email:

- Route through WordPress `wp_mail()` and the Algonquian Platform Mail Gateway when active.
- Log success/failure without storing protected message content unnecessarily.
- Use approved sender identity.
- Do not expose internal recipients in public HTML or JavaScript.
- Seller/property-submission workflows should generate a submission confirmation when an email address is supplied and consent/transaction rules permit it.
- Internal operational notifications should route to configured recipients instead of hard-coded developer addresses.

## 6. PDF production and archival rule

Whenever any Algonquian plugin generates a PDF:

1. Generate from server-authoritative data, not untrusted browser-calculated values.
2. Preserve source plugin, source record ID, deal ID where applicable, version, UUID, MIME type, size, and SHA-256 hash.
3. Store the authoritative PDF in the protected PDF & Signature Engine storage directory.
4. Register a corresponding **private Media Library attachment record** so administrators can locate the PDF in WordPress without exposing the private file as a normal public uploads URL.
5. Route Media Library access to the PDF Engine's protected download controller.
6. Send an archival copy to the configured ARE PDF delivery recipient; default: `algonquianre@gmail.com`.
7. Record whether Media Library registration and archival email succeeded or failed.
8. Never make delivery failure silently erase or overwrite the authoritative PDF record.
9. Do not treat an emailed attachment as the authoritative copy.

The default recipient is filterable through `algq_pdf_delivery_recipient` and configurable through the `algq_pdf_delivery_recipient` WordPress option.

## 7. Plugin-specific form gates

### Deal Intake

- Public seller/property intake.
- Internal intake.
- Quick capture.
- Homeowner-options intake where state-changing.
- Seller portal forms.
- Consent/version evidence.
- Attachment controls.
- Duplicate detection.
- Exactly-once Pipeline CRM handoff.
- Seller confirmation and internal notification.

### Buyer Portal and Deal Marketplace

- Buyer registration and profile data.
- Authentication and capability checks.
- Deal-specific authorization.
- Versioned NDA acceptance.
- Buyer interest/offer authorization against the exact deal.
- Protected package downloads.
- Proof-of-funds/document upload controls.

### Document Library

- Document request forms.
- Upload/edit forms.
- Package membership controls.
- Confidentiality, retention, expiration, and legal-hold enforcement.

### Funding Tracker

- Capital-source/lender/investor forms.
- Terms and commitment forms.
- Deal linkage validation.
- No public representations of guaranteed returns.

### Digital Store and WooCommerce Bridge

- Server-authoritative price/product checks.
- Terms/privacy acceptance where applicable.
- Payment-provider/webhook verification.
- Idempotent order and entitlement creation.
- Refund/cancellation entitlement revocation.

### Property Stewardship

- Owner authorization.
- Service-request forms.
- Record-level portal authorization.
- Private photographs/reports.
- Clear legal, fiduciary, caregiving, inspection, and insurance boundaries.

### MAO, Offer Generator, PDF & Signature, Automation, Command Center

Internal forms must require granular capabilities, strict controlled-value validation, nonces, protected record access, and append-only audit events for material state changes.

## 8. Required tests before production certification

Each form must have evidence for applicable tests:

- Valid submission.
- Missing required field.
- Invalid email/phone/number/date/enumeration.
- Expired/invalid nonce.
- Unauthorized user.
- Authenticated user without required capability.
- User attempting access to another user's/deal's record.
- Duplicate/replay submission.
- Rate-limit threshold.
- Oversized/forbidden attachment.
- Malformed upload.
- Database failure/partial failure.
- Mail delivery failure.
- PDF renderer failure.
- Media Library registration failure.
- Archival email failure.
- Successful PDF hash verification.
- Mobile and keyboard accessibility.
- WP_DEBUG with no PHP warnings/notices.

## 9. Production definition of done

A form may be marked **Production Ready** only when:

- All applicable controls above are implemented.
- Automated tests pass.
- A staging end-to-end transaction passes from rendered form through authoritative record creation and downstream handoff.
- Generated PDFs, when applicable, remain protected, appear as private Media Library records, and are delivered to the configured ARE archival mailbox.
- Audit evidence is available for material actions and delivery failures.
- No placeholder shortcode or placeholder form text remains on the production page.
