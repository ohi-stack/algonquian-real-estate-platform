# /documents Production Specification

## Purpose

The /documents page is the institutional document library and document-generation hub for Algonquian Real Estate. It should centralize entity records, lender packages, acquisition forms, due diligence documents, financial controls, risk documents, compliance records, and property management forms.

## Recommended Page Title

Documents

## Recommended URL

/documents

## Recommended Shortcode

```text
[algq_documents]
```

If the shortcode is not yet implemented, the page should temporarily render a categorized document library placeholder with links to each document category.

## WPBakery Implementation

Use:

```text
[vc_column_text]
[algq_documents]
[/vc_column_text]
```

Never use:

```html
</vc_column_text>
```

## Access Rule

The /documents page must be restricted to authorized internal users by default. Selected documents may be exposed through controlled lender, buyer, or tenant portals only when access is explicitly granted.

## Document Workflow

1. Internal user selects document category.
2. User selects source template or document type.
3. User links document to an entity, lender, buyer, tenant, or deal record if applicable.
4. System generates or stores document version.
5. User reviews document metadata.
6. Document is saved to the appropriate record.
7. Controlled access is granted if needed.
8. Download, generation, and signature events are logged.

## Production Requirements

- Page must be generated on plugin activation if it does not already exist.
- Page must not duplicate if the slug already exists.
- Page must use valid shortcode syntax.
- Document titles, descriptions, file URLs, and metadata must be escaped before output.
- File uploads must be validated by MIME type and extension.
- Download permissions must be enforced before serving files.
- Document generation actions must require capability checks and nonces.
- Document access should support internal, lender, buyer, tenant, and private access modes.
- Version history should be preserved.
- Material document events should be logged.
- Document records should link to deals, buyers, lenders, funding records, and tenant records where applicable.
- The page should support future PDF generation, signature workflow, package assembly, QR verification, retention rules, and secure portal access.
